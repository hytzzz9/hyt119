任务一 · 提示词工程师用两轮提示词让 AI 生成 #wySw4 的完整配置

需求拆解（写提示词前先列清单）

编号需求对应参数
①无缝循环loop: true
②3.2 秒自动翻页，手动操作后不停止autoplay: { delay: 3200, disableOnInteraction: false }
③圆点分页器且可点击跳转pagination: { el: '#wyPag4', clickable: true }
④初始效果为 cubeeffect: 'cube'

第 1 轮提示词

ROUND 1 · 需求描述较笼统
我 → AI 帮我用 Swiper 写一个轮播配置：要能循环，自动播放，带圆点，初始效果用立方体。
AI 回答（第 1 轮） 
new Swiper('#wySw4', {
  loop: true,
  autoplay: true,
  effect: 'cube',
  pagination: { el: '#wyPag4' }
});
这是一份最基础的配置，已经实现了循环、自动播放和立方体效果。

第 1 轮验证：逐项对照需求

需求第 1 轮结果判定
① 无缝循环已写 loop: true通过
② 3.2 秒自动翻页只写了 autoplay: true，使用默认 3 秒，且没有写 disableOnInteraction: false不通过
③ 圆点可点击缺少 clickable: true，圆点只能看不能点不通过
④ 初始效果 cube已写 effect: 'cube'，但 cubeEffect 阴影参数缺失，观感偏平基本通过

结论：第 1 轮 4 项需求里有 2 项不达标。原因是我的提示词只说了"要什么"，没有说清"具体数值"和"交互细节"，AI 只能用默认值填空。

第 2 轮提示词（把模糊词换成具体参数）

ROUND 2 · 精确到数值与交互行为
我 → AI 请基于 Swiper 11 生成初始化 #wySw4 的完整配置，逐条满足：
1）loop: true 无缝循环；
2）autoplay 每张停留 3200 毫秒，并且用户手动滑动或点圆点之后仍然继续自动播放（即 disableOnInteraction 必须为 false）；
3）分页器绑定 #wyPag4，且圆点可点击跳转（clickable: true）；
4）初始效果固定为 cube，动画时长 800 毫秒，并给出 cubeEffect 的 shadow / shadowOffset / slideShadows 建议值；
5）用一个函数封装，方便后续按不同 effect 重建实例。
AI 回答（第 2 轮） 
function createSwiper4(fx) {
  return new Swiper('#wySw4', {
    loop: true,
    effect: fx,
    speed: 800,
    autoplay: {
      delay: 3200,
      disableOnInteraction: false
    },
    pagination: {
      el: '#wyPag4',
      clickable: true
    },
    cubeEffect: {
      shadow: true,
      shadowOffset: 20,
      shadowScale: 0.94,
      slideShadows: true
    }
  });
}

var swiper4 = createSwiper4('cube');
把 effect 抽成参数后，切换效果时只需销毁旧实例再调用该函数即可。

第 2 轮验证结论

一句话结论：把"自动播放""圆点"这类模糊词替换成具体毫秒数、布尔值、元素 id 之后，第 2 轮配置 4 项需求全部达标，页面中 #wySw4 初始即为可自动翻页的立方体轮播。

  • loop 循环：最后一张继续往后翻会回到第一张 ✓
  • 自动播放 3.2 秒：静止 3.2 秒后自动切换 ✓
  • 手动拖拽后仍在继续自动播放 ✓
  • 点击圆点可直接跳转到对应展品 ✓

答辩：第 2 轮是怎么"说清楚"的

第一版提示词漏掉的是"手动操作后是否继续自动播放"和"圆点是否可点击"这两个交互细节，以及自动播放的具体时长。第二轮我没有写更多形容词，而是把每条需求翻译成"参数名 + 具体值 + 期望行为"三件套：

  • "自动播放" → delay: 3200 + disableOnInteraction: false
  • "带圆点" → el: '#wyPag4' + clickable: true
  • "立方体" → effect: 'cube' + 补充 cubeEffect 的阴影参数

AI 第一次给的代码错在：把 autoplay 直接写成布尔值 true，只能吃默认 3 秒，且默认在用户交互后停止；pagination 只传了 el，没写 clickable，圆点变成纯展示。

任务二 · creative 仿写课堂未讲的第 7 种 effect：creative 电影墙

官方示例阅读

对照 swiper/demo/257-effect-creative.html，第 3 个示例最接近"电影胶片墙"：上一张略微后退并左移，下一张从右侧推进。据此我改写成上一张缩小左移带角度、下一张放大右移进场。

最终代码（已写入 swiper-task.html） 
config.creativeEffect = {
  prev: {
    shadow: true,
    translate: ['-58%', 0, -320],
    rotate: [0, 0, -10],
    scale: 0.78,
    opacity: 0.6
  },
  next: {
    shadow: true,
    translate: ['58%', 0, -160],
    rotate: [0, 0, 10],
    scale: 1.08,
    opacity: 0.9
  }
};

用自己的话回答：prev / next 的 transform 各控制什么

字段含义
prev描述当前张左边那一张的姿态。translate 的 z 轴负值把它推到观众更远处（缩小、后退），rotate 给一点倾斜角，scale 再压小，整体形成"被翻过去的旧胶片"。
next描述当前张右边那一张的姿态。translate 的 x 轴正值把它放在右侧，z 轴负值稍小所以比 prev 更大，scale 略大于 1，看起来像是正被推进画面。
translate数组三个值依次为 x、y、z 轴位移，理解方式与 CSS transform: translate3d 一致。
rotate / scale / opacity / shadow / origin分别控制旋转角度、缩放比例、透明度、阴影开关、变换原点。

答辩：百分号是相对谁的

translate 中的百分比是相对该 slide 自身尺寸（更准确说是相对容器尺寸）计算的，不是相对视口：['58%', 0, -160] 表示沿 x 轴移动约半张多卡片宽度，-160 是不带单位的像素值，直接沿 z 轴后退 160px。

改数值实验：把 next.rotate 从 [0, 0, 10] 改成 [0, 0, 20]，下一张卡片的倾斜角立刻变大，卡片右下角会明显下压，胶片墙的"歪斜感"更强。

② 超纲能力：keyboard 键盘控制

我选的是 keyboard 键盘控制——课堂上只讲了拖动、圆点和自动播放，键盘切换没有讲。开启后把焦点放在轮播上，按 ← / → 方向键即可切换展品。

keyboard: {
  enabled: true,        // 开启键盘控制
  onlyInViewport: true  // 只有当轮播在可视区域内才响应，避免和页面滚动打架
}

与 AI 的关键往返

我 → AI Swiper 里怎么让轮播支持键盘左右键切换？有没有什么坑？
AI 回答 用 keyboard: { enabled: true } 即可。注意默认页面上下方向键也会被拦截，长页面滚动会受影响，建议加 onlyInViewport: true，只让当前可见的轮播响应。
我 → AI（追问） 那如果我给它加 onlyInViewport: true，页面同时有 4 个轮播时会不会互相抢按键？
AI 回答 不会。每个实例只在自己的容器进入视口时监听，同一时刻视口内通常只有一个轮播处于激活状态。

答辩四连问

  • 这段代码什么意思？keyboard.enabled 开启方向键导航，onlyInViewport 限制仅可见时生效。
  • AI 第一次给的东西不对，你改了什么？AI 只给了 keyboard: { enabled: true }，实测上下方向键会抢走页面滚动，所以补了 onlyInViewport: true。
  • 新参数的作用？避免多个轮播同时监听键盘事件、避免影响页面正常滚动。
  • 把 delay 改成指定值并解释预期变化？把 autoplay.delay 从 3200 改成 1500，每张展品停留时间缩短到 1.5 秒，翻页节奏明显变快；改成 6000 则变成缓慢浏览、适合细看展品说明。
